# نظام إدارة بلاغات الصيانة والتشغيل — مستشفى الأمير محمد بن ناصر (جازان)

نظام ويب متكامل لاستقبال ومتابعة بلاغات الصيانة والتشغيل في المستشفى: نموذج بلاغ
عام مع مرفقات (صور/فيديو) ورمز QR لكل بلاغ، تتبّع البلاغ برقمه، لوحة تحكم إدارية
بتحديث لحظي، إشعارات فورية (بريد/تيليجرام/واتساب)، دورة حياة كاملة للبلاغ، صلاحيات
وأدوار، تقارير وتصدير Excel/PDF، ملف Excel لحظي شجري، دعم عربي/إنجليزي ووضع ليلي،
وقاعدة بيانات سحابية (Neon PostgreSQL) تعمل 24/7 مع keep-alive تلقائي.

> هذا مشروع مستقل تماماً. لا يشارك أي جدول أو ملف مع أي مشروع آخر.

---

## 1) الميزات

### تقديم البلاغ (عام، بدون تسجيل دخول)
- نموذج شامل: القسم، المبنى/الطابق/الغرفة، نوع العطل، الوصف، درجة الأهمية،
  بيانات المبلّغ (الاسم/الجوال/البريد)، هل يؤثر على السلامة / استمرارية العمل.
- ربط تلقائي لنوع العطل ← التخصص والفني المسؤول.
- مرفقات: صور (JPEG/PNG/GIF/WEBP) وفيديو (MP4/WEBM/MOV/MKV) بحجم أقصى 15MB.
- رقم بلاغ تلقائي بصيغة `HM-YYYY-NNNNN` + صفحة تتبّع عامة `/track/{ticket_no}`.
- **رمز QR/باركود** لكل بلاغ (صفحة النجاح + التتبّع + بطاقة طباعة `/card/{ticket}`)
  وآخر عالي الدقة في تقرير PDF.
- قائمة أنواع الأعطال + خيار **«أخرى»** مع حقل وصف حر إلزامي.
- منع البلاغات المكرّرة خلال نافذة زمنية قصيرة.

### لوحة التحكم الإدارية (`/dashboard`) — للمسؤول فقط
- محصورة على دور `admin` (غير المسجَّل ← `/login`، وغيره ← 403). نموذج البلاغ يبقى عاماً.
- مؤشرات KPI: الإجمالي، مفتوحة، متأخرة عن SLA، مكتملة، متوسط زمن الاستجابة والحل.
- تحديث لحظي عبر **SSE** (`/api/stream`) مع تنبيه/صوت عند وصول بلاغ جديد.
- فلاتر (الحالة، الأولوية، القسم، البحث)، جداول، رسوم بيانية (Chart.js محلي).
- أداء الفنيين، مواقع البلاغات المتكررة، قنوات الإشعارات وحالة التسليم.
- رابط تنزيل **ملف Excel اللحظي الشجري** (`/reports/export/live`) الذي يُحدَّث تلقائياً مع كل بلاغ.

### دورة حياة البلاغ (7 حالات + إلغاء)
`مُستلم → تم الاستلام → قيد التنفيذ → معلّق → تم الإنجاز → مغلق` وحالة `ملغي`،
مع تعيين فني/فريق/تخصص، ملاحظات داخلية، تعليقات، تعديل، وإدارة المرفقات.

### الإعدادات (`/settings`)
إدارة الأقسام، التخصصات، أنواع الأعطال، الفنيين، المستخدمين، مواعيد SLA،
وإعدادات عامة — كلها من الواجهة دون كود.

### التقارير والتصدير (`/reports`)
تقارير بفلاتر + تصدير **Excel** (`/reports/export/excel`) و**PDF عربي**
(`/reports/export/pdf`) بخط عربي مُشكّل.

### الأدوار والصلاحيات (6 أدوار)
`viewer < staff < technician < maint_supervisor < maint_manager < admin`.

### سجل التدقيق
كل تغيير حالة/تعيين/تعديل يُسجَّل في `complaint_events` مع المستخدم والوقت.

### تصفير السجل (`/settings` ← عام)
زر «تصفير سجل البلاغات» (بتأكيد نصي) يحذف كل البلاغات ويعيد العدّاد ليبدأ من
`HM-2026-00001` من جديد — مع الحفاظ على الأقسام والأنواع والفنيين والمستخدمين.

### اللغتان والوضع الليلي
- تبديل عربي/إنجليزي (RTL/LTR) عبر `/set-lang/{ar|en}` — الترجمة من `app/i18n.py`
  وتشمل الصفحات والقوالب والنصوص المُمرَّرة إلى JavaScript اللحظي.
- وضع ليلي/نهاري يُحفظ في `localStorage` ويُطبَّق قبل الرسم (بدون وميض).

## 2) التقنيات

| الطبقة | التقنية |
|-------|---------|
| الواجهة الخلفية | FastAPI + Uvicorn |
| القوالب | Jinja2 (RTL عربي) |
| قاعدة البيانات | Neon PostgreSQL (سحابي) / SQLite (محلي) |
| بلا محرك ORM — طبقة اتصال موحّدة | `app/db.py` (psycopg3 / sqlite3) |
| الإشعارات | SMTP، Telegram Bot API، WhatsApp Cloud API |
| التصدير | openpyxl (Excel)، reportlab + arabic-reshaper + python-bidi (PDF) |
| الرسوم | Chart.js (محلي) + SSE للتحديث اللحظي |

## 4) التشغيل المحلي

### ويندوز (الأسهل)
```bat
start.bat
```
ينشئ بيئة افتراضية، يثبّت المتطلبات، يزرع البيانات، ثم يشغّل الخادم على
`http://127.0.0.1:8000`.

### يدوياً (أي نظام)
```bash
python -m venv .venv
.venv\Scripts\activate        # ويندوز
# source .venv/bin/activate   # لينكس/ماك
pip install -r requirements.txt
python -m app.seed            # بيانات أولية (آمنة للتكرار)
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### الروابط

| الصفحة الرئيسية | `/` |

| التقارير | `/reports` |
| الإعدادات | `/settings` |
| بطاقة طباعة بلاغ | `/card/{ticket_no}` |

## 6) قاعدة البيانات (Neon)

1. أنشئ مشروعاً على [Neon](https://neon.tech) ثم قاعدة باسم `hospital_maintenance`.
2. انسخ Connection String (مع `sslmode=require`).
3. ضعه في `.env`:
   ```
   DATABASE_URL="postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require&channel_binding=require"
   ```
4. شغّل `python -m app.seed` لإنشاء الجداول والبيانات الأولية.
   إذا كان `DATABASE_URL` فارغاً يُستخدم ملف SQLite محلي تلقائياً.

> طبقة `app/db.py` تعيد الاتصال تلقائياً عند انقطاع جلسة Neon (AdminShutdown /
> scale-to-zero) مع إعادة محاولة للاستعلام، لذا يبقى النظام يعمل بسلاسة.

## 7) الإشعارات (اختيارية)

تُسجَّل كل محاولة إرسال في `notification_log` وتظهر حالتها في اللوحة.

### بريد إلكتروني (Gmail)
`SMTP_USER` و `SMTP_PASSWORD` (App Password) و `NOTIFY_TO`.

### تيليجرام
أنشئ بوت عبر `@BotFather` ← `TELEGRAM_BOT_TOKEN`، واقرأ معرّف المحادثة من
`@userinfobot` ← `TELEGRAM_CHAT_ID`.

### واتساب (Meta Cloud API)
`WHATSAPP_TOKEN` و `WHATSAPP_PHONE_ID` و `WHATSAPP_TO`.

أي قناة تُترك فارغة تُعطَّل بصمت.

## 8) النشر على Render

المشروع جاهز للنشر عبر `render.yaml`:

1. ارفع المستودع إلى GitHub.
2. على [Render](https://render.com) اختر **New → Blueprint** وحدّد المستودع.
3. Render يقرأ `render.yaml` تلقائياً. أدخل قيم المتغيّرات السرّية:
   `DATABASE_URL`, `BASE_URL`, `SMTP_*`, `TELEGRAM_*`, `WHATSAPP_*`.
4. سيعمل التطبيق على `https://<name>.onrender.com`.

> ملاحظة: قرص Render المجاني مؤقّت؛ مرفقات الملفات تُفقد عند إعادة النشر.
> للإنتاج طويل الأمد استخدم تخزين كائنات (S3/Neon Object Storage) للمرفقات.

## 9) الإبقاء مستيقظاً 24/7 (keep-alive)

استضافات الطبقة المجانية (مثل Render) تُنيم الخدمة بعد خمول ~15 دقيقة. للعمل 24/7:

1. **GitHub Actions** (مُهيّأ في `.github/workflows/keepalive.yml`): ينفّذ طلب HTTP
   إلى `BASE_URL/health` كل 10 دقائق. أضف في المستودع
   **Settings → Secrets and variables → Actions**: متغيّر `BASE_URL`
   (مثل `https://hm.example.com`) أو سرّ بنفس الاسم.
2. **بديل (تشغيل محلي/خادم دائم)**: `python keepalive.py`
   مع متغيّر البيئة `BASE_URL` و`INTERVAL` (بالثواني، افتراضي 600).

> ملاحظة: GitHub قد يؤخّر المهام المجدولة وقت الذروة؛ لمزيد من الثبات استخدم
> مزوّد مراقبة (UptimeRobot / cron-job.org) يطلب `/health` كل 5 دقائق.

## 11) ملاحظات أمان

- لا تُرفع `.env` إلى Git (مستثنى في `.gitignore`).
- استخدم `SECRET_KEY` عشوائياً طويلاً في الإنتاج.
- القيم الحسّاسة في Render تُدار كـ Environment Variables وليس في الكود.
- قيّد حجم/نوع المرفقات (مطبّق مسبقاً: 15MB لأنواع محددة).
